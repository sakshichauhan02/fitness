========================================================================
FITAI - TECHNICAL ARCHITECTURE, FILE IMPLEMENTATIONS & CONNECTION LOGICS
========================================================================

This document details the functional logic, API usage, and connection flows across the frontend (Next.js) and backend (FastAPI) components of the FitAI application.

------------------------------------------------------------------------
1. CORE ARCHITECTURAL FLOW & LOGIC STEPS
------------------------------------------------------------------------

* STEP 1: Authentication Gateway (/login)
  - Objective: Authenticate user access.
  - Sandbox/Mock Flow: Sets client-side cookies ('fitai-mock-session=true' and 'fitai-mock-profile') to bypass API databases.
  - Production Flow: Uses Supabase Auth to register or log in the user, linking their session to a live PostgreSQL backend.

* STEP 2: Middleware Route Guard (src/middleware.ts)
  - Objective: Protect dashboard routes.
  - Implementation: Intercepts requests, validates either the mock cookies (Sandbox) or Supabase JWT tokens (Production), and routes unauthenticated users back to '/login'.

* STEP 3: Onboarding Verification (src/app/dashboard/layout.tsx)
  - Objective: Ensure every logged-in user has biometric data.
  - Logic: Checks the database or mock cookies for 'onboarded = true'. If false, automatically redirects the user to `/onboarding`.

* STEP 4: Onboarding Form (src/app/onboarding/page.tsx)
  - Objective: Collect and standardise biometric information (Height in cm, Weight in kg, Target goals, Dietary preferences, and Equipment access).
  - Calculations: Converts units (lbs to kg, ft/in to cm) and saves the profile.

* STEP 5: Metric Computations (src/app/dashboard/page.tsx)
  - Objective: Calculate BMR, TDEE, Calories, and Macronutrient splits.
  - Equations:
    * BMR (Mifflin-St Jeor):
      - Men: 10 * Weight(kg) + 6.25 * Height(cm) - 5 * Age(yrs) + 5
      - Women: 10 * Weight(kg) + 6.25 * Height(cm) - 5 * Age(yrs) - 161
      - Other: 10 * Weight(kg) + 6.25 * Height(cm) - 5 * Age(yrs) - 78
    * TDEE: BMR * 1.375 (Moderate Activity Coefficient)
    * Calorie Target:
      - V-Taper Focus: TDEE - 150 kcal
      - Lean Bulk: TDEE + 300 kcal
      - Aggressive Cut: TDEE - 500 kcal
      - Strength: TDEE + 100 kcal
    * Macronutrients:
      - Protein: 2.0g per kg of bodyweight
      - Fats: 25% of Target Calories (9 kcal/g)
      - Carbs: Remainder of Calories (4 kcal/g)

------------------------------------------------------------------------
2. APIS USED & CONNECTION LOGIC
------------------------------------------------------------------------

* FRONTEND TO BACKEND CONNECTION:
  - The Next.js frontend calls the FastAPI backend (running on `http://localhost:8000`) using standard `fetch` API requests.
  - The backend CORS middleware allows origins from `http://localhost:3000`.

* BACKEND TO AI SERVICES (Gemini API):
  - Model: `gemini-2.5-flash`
  - Integration: Calls `google.generativeai.GenerativeModel` using structured JSON outputs (`generation_config={"response_mime_type": "application/json"}`).
  - Fallbacks: In the absence of a configured `GEMINI_API_KEY`, the server falls back to returning structured mock data mirroring the expected response models.

* BACKEND ROUTERS & ENDPOINTS:
  1. Profile Endpoints (`/profile`)
     - POST `/profile/sync`: Synchronises profile data from frontend state.
  2. Workout Endpoints (`/workouts`)
     - POST `/workouts/generate`: Sends user profile details to Gemini to generate weekly splits, daily exercise plans, and coaching tips.
  3. Nutrition Endpoints (`/nutrition`)
     - POST `/nutrition/generate`: Generates personalized meals and food swaps matching daily calorie and macro goals.
     - POST `/nutrition/analyze-meal`: Uses natural language processing to estimate calories, ingredients, and macro splits of an described meal.
